# INTEGRATION_POS — боевое подключение обращений граждан (Ф7, Ф8)

## Источники

- **ПОС «Госуслуги. Решаем вместе»** (Платформа обратной связи) — основной канал обращений.
- **Электронная приёмная Правительства Тульской области** — региональный канал.
- Отраслевые обращения (агрегаты для тепловой карты удовлетворённости, Ф7).

На MVP — `FeedbackChannelProvider=mock` / `AppealsDataProvider=mock`: обращение сохраняется
в свою БД, выдаётся имитация номера обращения, статусы жизненного цикла отрабатывают локально.
Агрегаты удовлетворённости генерируются детерминированно (seed) и помечены `isMock`.

## Требования к боевому этапу (этап 2)

1. **Регистрация в ПОС** и получение прав интеграции (виджет/SDK + серверный обмен).
2. **Авторизация через ЕСИА (OIDC):** для расширенных сценариев подачи (статус в личном
   кабинете, история). OIDC-провайдер ЕСИА, короткие JWT + refresh, маппинг `esia_id` в
   `appeals.esia_ref` и `users.esia_id`.
3. **Формат передачи обращения:** категория (справочник §7 Ф8), объект (из реестра либо
   «нет в списке»), геометка, адрес/ориентир, описание, фото/видео (до 5 файлов ≤10 МБ,
   EXIF-дата/геолокация), согласие на обработку ПДн (152-ФЗ), контакты (опционально при
   анонимной подаче).
4. **Получение идентификатора** `pos_ticket_id` при создании обращения в ПОС.
5. **Синхронизация статусов:** `new → in_review → accepted → forwarded (в ПОС/приёмную/
   подрядчику) → resolved | rejected`; SLA по категории — из справочника; обратная
   синхронизация статуса из ПОС по `pos_ticket_id`.
6. **Уведомления автору:** email/СМС (на MVP — заглушка).
7. **Журналирование:** все действия модерации — в `audit_log` (§9); ПДн в логах не хранятся.

## Схема обмена (целевая)

```
Форма жалобы (web) ──► POST /api/v1/appeals (multipart, Idempotency-Key)
   ──► FeedbackChannelProvider(live): создание в ПОС → pos_ticket_id
   ──► appeals (своя БД) + audit_log
   ◄── вебхук/опрос ПОС: обновление статуса → appeals.status → уведомление автору
Публичная лента «решённые проблемы» — обезличенная (description_anonymized, без ПДн).
```

## Анти-спам и защита

- Rate limit: не более `RATE_LIMIT_APPEALS_PER_10MIN` обращений с IP за 10 минут.
- Капча, фильтр дублей (категория + радиус 100 м → «похожая жалоба уже есть», предложить
  поддержать), блокировка по ключевым словам (конфигурируемо).
- Идемпотентность POST (`Idempotency-Key`), клиентская валидация, черновик в localStorage.

## Деградация

При недоступности ПОС — обращение сохраняется в свою БД со статусом `new` и пометкой
«ожидает отправки в ПОС»; повторная синхронизация при восстановлении связи.

## Трудозатраты (этап 2)

10–15 чел-дн: регистрация/соглашение, OIDC-ЕСИА, серверный обмен и вебхуки статусов,
анонимизация ленты, регрессионные тесты.
