# INTEGRATION_EIS — боевое подключение данных о закупках (Ф6)

## Принцип

На MVP блок «Закупки и контракт» работает на **мок-данных** (`ProcurementProvider=mock`):
цены детерминированно вычисляются от площади/мощности и отрасли (конфиг
`@oks/shared/config/mockGeneration`), округляются до тыс. ₽, привязываются к реальным
подрядчикам/срокам из реестра и помечены `isMock=true` + бейджем «ДЕМО-ДАННЫЕ» и
дисклеймером «не являются сведениями из ЕИС».

**Скрапинг `zakupki.gov.ru` в MVP и далее НЕ реализуется** (§15.5, требование ТЗ).

## Юридически корректные варианты получения боевых данных

1. **Открытые данные и выгрузки ЕИС.** ЕИС публикует наборы открытых данных и предоставляет
   открытые API-сервисы для зарегистрированных потребителей. Оформление доступа — по
   регламенту ЕИС/Казначейства; данные — по реестровым номерам закупок/контрактов.
2. **Региональный портал закупок малого объёма** `zakupki.tularegion.ru` — обмен по
   соглашению с оператором портала (выгрузки по заказчикам региона).
3. **Регламентный обмен по соглашению** между Министерством строительства ТО и
   держателями данных (ЕИС/региональный портал): периодические выгрузки (CSV/JSON/XML)
   по списку объектов/заказчиков, загрузка через `ProcurementProvider=live`.

## Схема обмена (целевая)

```
ЕИС / региональный портал  ──(регламентная выгрузка: JSON/XML по реестровым номерам)──►
   apps/api: ProcurementProvider(live)  ──►  contracts (source=eis|regional)
                                          ──►  производные: цена за м²/место, индикаторы риска
```

Поля контракта (§7 Ф6): реестровый номер, предмет, способ определения поставщика, дата
заключения, НМЦК/цена, этап исполнения, статус, сроки, исполнитель, изменения/расторжение,
аванс, гарантии, источник, ссылка на первоисточник, дата последнего обновления.

## Производные показатели и риски

- «Стоимость за м² / за место» — с пометкой методики расчёта.
- Индикатор риска: срок истёк при готовности < 100 %; неоднократные переносы сроков.

## Деградация

При недоступности источника — последние загруженные данные + дата обновления; при полном
отсутствии — блок с мок-данными и явной пометкой демо-режима.

## Трудозатраты (этап 2)

8–12 чел-дн: согласование доступа/соглашения, приёмник выгрузок, маппинг в `contracts`,
регрессионные тесты, документирование регламента обновления.
