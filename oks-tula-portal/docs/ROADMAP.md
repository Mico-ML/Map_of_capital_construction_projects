**Итерации 0–4 выполнены и верифицированы в песочнице:** 223 unit-теста зелёные,
`tsc` (strict) и ESLint чистые, сборка shared/etl/api(+seed)/web успешна (web — 1093 модуля,
`AccessibilityPage` вынесен в ленивый чанк 21,8 КБ), `prisma validate` проходит, миграция
`0002_isochrone_accessibility` сверена с `schema.prisma` через `prisma migrate diff`.

Итерация 3: режимы сравнения «До/В процессе/После», таймлапс, камеры-заглушки с «живым»
таймстемпом, демо-медиа на 10 объектах, `docs/IMAGERY.md`.

Итерация 4 (Ф4): адаптеры `IsochroneProvider`/`PoiProvider` (мок + боевые клиенты Isochrone
и Search API 2ГИС с ретраями, таймаутом 15 с, обработкой `status != "OK"`, HTTP 204/429),
собственный WKT ⇄ GeoJSON-парсер, кэш зон в PostGIS `isochrone_cache` (TTL 30 суток,
single-flight, повторный запрос к API исключён), отрисовка зон `mapgl.Polygon` с градацией
по времени и легендой, переключатель «от объекта / к объекту», отчёт доступности
(площадь зоны, население, жилые дома, POI по сферам, объекты той же сферы из реестра,
вердикт + методика + дисклеймеры), страница пакетного режима `/accessibility`
(сводное покрытие и «белые пятна» через `ST_Union`/`ST_Difference`/`ST_Area`), прокси
рубрикатора `GET /geo/rubrics`, миграция и 86 новых unit-тестов (WKT, демо-модель,
боевые клиенты на образцах из документации 2ГИС, расчёт отчёта, разбор параметров).

Прогон `docker compose up` и e2e (Playwright: `object-flow`, `media-flow`, `isochrone-flow`) —
на машине заказчика (в песочнице нет Docker/PostgreSQL/браузеров). Боевой расчёт зон
требует `ROUTING_API_KEY` (`ISOCHRONE_PROVIDER=live`); до его появления зоны в демо строятся
явной геометрической моделью с бейджем «ДЕМО-ДАННЫЕ» (`DECISIONS` D18) либо отключаются
`ISOCHRONE_MOCK_GEOMETRY=false`.

## Дорожная карта до продакшена (§14)

### Этап 2 — боевые интеграции
Подключение ЕИС/регионального портала закупок по соглашению (без скрапинга); ПОС
«Госуслуги. Решаем вместе» и электронная приёмная Правительства ТО (авторизация ЕСИА/OIDC,
синхронизация статусов); реальные HLS-потоки камер подрядчиков с медиа-сервером
(MediaMTX/nginx-rtmp); подготовка архивных мозаик Sentinel-2/Landsat и выкладка на WMS;
официальные данные Росстата и/или операторов связи по населению; официальные границы МО
(ОКТМО/картографический фонд) вместо OSM.

### Этап 3 — масштабирование и данные
PostgreSQL с репликацией и Redis-кэшем; S3-совместимое хранилище медиа с CDN;
полнотекстовый поиск; версионность данных реестра; регламентный импорт из ведомственных
систем (API/выгрузки) вместо CSV; мониторинг и алерты; нагрузочное тестирование; PWA и push.

### Этап 4 — зрелость и соответствие
Аттестация по требованиям ИБ (приказ ФСТЭК №17/21), размещение в ГИС/аттестованном контуре;
включение в реестр отечественного ПО (Postgres Pro, Astra/РЕД ОС при необходимости); полная
доступность по ГОСТ Р 52872-2019 (внешняя экспертиза); многоязычность при необходимости;
публичный API и открытые данные; ML-модель прогнозирования срыва сроков по динамике
готовности; интеграция с ЕГИСКО/ИСОГД; публикация индекса качества городской среды по МО.
