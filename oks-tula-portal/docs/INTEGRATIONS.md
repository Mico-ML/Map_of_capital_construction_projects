# INTEGRATIONS — интеграции по принципу «мок сейчас — боевое подключение позже» (§10)

Каждая внешняя интеграция — за интерфейсом-адаптером, выбираемым переменной окружения
`*_PROVIDER=mock|live`. Контракт описан типами (`packages/shared`, `etl/src/geocode/types.ts`);
мок возвращает структурно идентичные данные с флагом `isMock`. Переключение mock → live
не требует изменения UI и бизнес-логики.

| Интеграция | Интерфейс | MVP (итерация 0–1) | Боевой этап: что требуется | Ответственный / доступ | Деградация при недоступности |
|---|---|---|---|---|---|
| Карта (MapGL) | `MapProvider` (браузер) | **LIVE** при наличии `VITE_MAPGL_KEY` | Подписка/квоты, домен-ограничения ключа | Заказчик / platform.2gis.ru | Заглушка + список/таблица объектов |
| Изохроны | `IsochroneProvider` | **MOCK** — детерминированная геометрическая модель зоны (`isMock=true`, бейдж «ДЕМО-ДАННЫЕ», `ISOCHRONE_MOCK_GEOMETRY=false` отключает и её) | `ROUTING_API_KEY` + `ISOCHRONE_PROVIDER=live`; кэш PostGIS 30 суток | Заказчик / 2ГИС (подписка Navigation API) | Зона не строится; карточка и отчёт показывают «Нет данных» с причиной |
| Геокодинг | `GeocoderProvider` | **MOCK** (координаты не выдумываются) | `CATALOG_API_KEY`, `region_id=36` | Заказчик / 2ГИС | Объекты без координат — в очереди геокодирования |
| POI (Search) | `PoiProvider` | **MOCK** — POI не запрашиваются и не выдумываются (`count=null`, «Нет данных»); сопоставление объектов той же сферы — по реальному реестру ОКС | `CATALOG_API_KEY` + `POI_PROVIDER=live`, верификация рубрикатора (см. ниже) | Заказчик / 2ГИС | В отчёте нет числа POI/жилых домов; вердикт — с достоверностью `low/medium` |
| Рубрикатор (Categories) | `PoiProvider.searchRubrics` | **MOCK** (помета без данных) | `CATALOG_API_KEY`; прокси `GET /api/v1/geo/rubrics?q=` | Заказчик / 2ГИС | Алиасы рубрик не заполняются — поиск идёт по документированному `q` |
| Закупки (ЕИС) | `ProcurementProvider` | **MOCK** (детерминированные цены, `isMock`) | Соглашение об обмене / открытые данные / регламентная выгрузка | см. `INTEGRATION_EIS.md` | Блок «Закупки» с пометкой демо |
| Обращения (ПОС) | `FeedbackChannelProvider` / `AppealsDataProvider` | **MOCK** (сохранение в свою БД + имитация номера) | Регистрация в ПОС, OIDC/ЕСИА, схема обмена | см. `INTEGRATION_POS.md` | Форма валидируется; отправка — в свою БД |
| Камеры подрядчиков | `CameraProvider` | **MOCK** (публичный тестовый HLS + таймстемп) | Согласие подрядчика, HLS/RTSP, медиа-сервер, токены | Подрядчики / медиа-сервер | Статичный кадр + «камера недоступна» |
| Архивные снимки «До» | `HistoricalImageryProvider` | **MOCK** + `docs/IMAGERY.md` | Мозаики Sentinel-2/Landsat, свой WMS/WMTS (GeoServer) | Заказчик / GeoServer | Слой «До» — плейсхолдер + «история места» |
| Рендеры «После» | `MediaStorage` | Загрузка в админке (итерация 3) | Регламент получения, права использования | Заказчики/проектировщики | Блок «Материалы не предоставлены» + форма запроса |
| Население/плотность | `PopulationProvider` | **MOCK** CSV (источник+год) | Выгрузки Росстата по МО / операторы связи | Росстат / операторы | «светофор» на демо-населении с пометкой |

## Верификация рубрикатора POI перед боевым подключением (итерация 4)

`config/poi_rubrics.ts` намеренно не содержит придуманных `alias`/`id`
(`rubricIds=null`, `aliases=[]`, `verifiedAgainstDocs=false`, §15.2/§15.3). Порядок действий
при появлении `CATALOG_API_KEY`:

1. `GET /api/v1/geo/rubrics?q=детские сады` (прокси Categories API
   `https://catalog.api.2gis.com/2.0/catalog/rubric/search?q=…&region_id=36`) — получить
   реальные `id`, `alias`, `name`, `parent_id` рубрик региона 36.
2. Повторить для всех `rubricQueries` конфига (детсады, школы, лицеи, гимназии, поликлиники,
   амбулатории, стационары, спорткомплексы, стадионы, спортплощадки, бассейны, ДК,
   библиотеки, музеи, котельные, ТЭЦ, подстанции, жилые дома).
3. Заполнить `rubricIds` и `aliases`, поставить `verifiedAgainstDocs: true`, зафиксировать
   дату и версию рубрикатора в комментарии; прогнать `npm test` (классификация покрыта тестами).
4. Проверить выдачу: `GET /api/v1/objects/{id}/accessibility-report?allSpheres=true&refreshPoi=true`
   — в `poi[].matchedBy` видны использованные запросы и метод (`polygon` / `point_radius`).

**Ограничение Search API:** допустимая площадь `polygon` ~6 км² → при больших зонах
автоматически применяется `point`+`radius` с постфильтрацией (см. `DECISIONS` D21).

## Требования к гибридному переходу

Для каждой интеграции фиксируются: ответственный, способ получения доступа, формат обмена,
частота обновления, деградация при недоступности, оценка трудозатрат (см. таблицы выше и
профильные документы `INTEGRATION_EIS.md`, `INTEGRATION_POS.md`, `IMAGERY.md`).

**Оценка трудозатрат (укрупнённо, этап 2):** изохроны + POI (Navigation/Search API) —
2–4 чел-дн (подписка, ключи, верификация рубрикатора, сверка зон на 3–5 объектах); ЕИС — 8–12 чел-дн (соглашение + приёмник
выгрузок); ПОС + ЕСИА/OIDC — 10–15 чел-дн; камеры + медиа-сервер — 6–10 чел-дн; архивные
мозаики + WMS — 10–20 чел-дн (зависит от подготовки снимков); официальные границы и
население — 3–5 чел-дн (при наличии выгрузок).

## Принципы

1. Скрапинг `zakupki.gov.ru` **не используется** (§15.5) — только официальные механизмы.
2. ПДн не отправляются в сторонние сервисы; обращения публикуются обезличенными.
3. Все вызовы 2ГИС (кроме MapGL) — через бэкенд-прокси с кэшем и лимитами (§4.5).
4. Ключи — только в `.env`; в логах и бандле — отсутствуют (§15.11).
