# ARCHITECTURE — архитектура портала

## Обзор

Монорепозиторий (npm workspaces) из четырёх пакетов и данных:

```
┌─────────────┐   HTTP /api/v1    ┌──────────────┐   SQL/PostGIS   ┌────────────────┐
│  apps/web   │ ────────────────► │  apps/api    │ ──────────────► │ PostgreSQL 16  │
│ React+Vite  │   (nginx proxy)   │   NestJS     │   Prisma        │  + PostGIS 3.4 │
│  MapGL 2ГИС │                   │  REST+Swagger│                 └────────────────┘
└──────┬──────┘                   └──────┬───────┘
       │ MapGL (публичный ключ)          │ прокси (секретные ключи)
       ▼                                  ▼
   2ГИС тайлы/карта               2ГИС Isochrone/Catalog/Search API
                                          │
                              ┌───────────┴───────────┐
                              │  адаптеры-провайдеры   │
                              │  mock ⇄ live (§10)     │
                              └───────────────────────┘
```

- **`packages/shared`** — единый источник правды: типы контрактов API, справочники
  (статусы, отрасли, МО с ОКТМО, единицы мощности, категории жалоб), конфигурация
  (регион 2ГИС, палитра «светофора», пороги/веса, рубрикаторы POI), утилиты
  (форматирование дат/чисел в русской локали, склонения, «разноска» дублей координат,
  детерминированный PRNG, формула индекса удовлетворённости). Импортируется web, api и etl.
- **`etl`** — чистые функции парсинга/нормализации `objects.csv`, геокодинг-пайплайн
  (§6.3), контроль качества геометрии, построитель отчёта `data_quality`. Без зависимостей
  от БД (сухой прогон) + загрузчик (используется сидом API).
- **`apps/api`** — NestJS: REST `/api/v1`, прокси 2ГИС с кэшем и rate limiting,
  производные метрики, Prisma+PostGIS. Модули: `objects`, `dictionaries`, `municipalities`,
  `analytics`, `data-quality`, `geo`, `health`.
- **`apps/web`** — SPA React 18: карта MapGL, список/фильтры, карточка объекта, аналитика,
  форма жалобы, служебный вход. Состояние: Zustand (UI) + TanStack Query (серверные данные).

## Ключевые принципы

1. **Все запросы к 2ГИС (кроме MapGL в браузере) — через бэкенд-прокси** `/api/v1/geo/*`
   с кэшем (TTL изохрон 30 сут, геокод 90 сут), rate limiting по IP и ретраями (§4.5).
   Секретные ключи никогда не покидают бэкенд (§15.11).
2. **Адаптеры mock ⇄ live** (§10): каждая внешняя интеграция — за интерфейсом
   (`GeocoderProvider`, `IsochroneProvider`, `ProcurementProvider`, …), выбираемым
   переменной окружения. Мок возвращает структурно идентичные данные с `isMock`.
   Переключение не требует правки UI/бизнес-логики.
3. **Ничего не выдумываем** (§15.1): нет значения → `null` + «Нет данных» в UI;
   синтетика — только через `data/mock/` с флагом `isMock` и бейджем «ДЕМО-ДАННЫЕ».
4. **Трассируемость**: каждая исходная строка хранится целиком в `objects.raw` (JSONB)
   с `source_row_number` и `source_file_hash`; любая производная цифра сверяется с источником.
5. **Идемпотентность**: ETL и сид повторяемы; `manual_override` защищает ручные правки (§6.1 п.10).

## Геоданные (PostGIS)

- Границы МО — `municipalities.geom` (MultiPolygon, 4326), источник OSM (ODbL), `geom_is_mock=false`.
- Точки объектов — `objects.geom` (Point, 4326); при отсутствии — отображение на центроиде
  МО (`municipalities.center`) с флагом `locationApproximate`.
- Определение МО — `ST_Contains` (контроль согласованности с колонкой «АМО»).
- Выборка по карте — `ST_Intersects` + `ST_MakeEnvelope` (bbox), GiST-индексы.
- Кэш изохрон — `isochrone_cache` (MultiPolygon + `start_point`, `area_m2`, `poi_snapshot`),
  уникальность по `(object, transport, duration, reverse)`; повторный запрос к API при
  кэш-попадании запрещён (§4.2), параллельные одинаковые запросы склеиваются (single-flight).
  Флаг `is_mock` разделяет боевой расчёт 2ГИС и демо-модель: выдача фильтруется по текущему
  режиму провайдера, поэтому демо-зона никогда не показывается как результат API.
- Зоны, покрытие и «белые пятна» считаются в PostGIS (`ST_Area`, `ST_DWithin`,
  `ST_Union`, `ST_Intersection`, `ST_Difference`, `ST_SimplifyPreserveTopology`) —
  браузер получает только готовые GeoJSON и числа (§15.6).

## Производительность и надёжность (§9)

- 95 объектов грузятся одним запросом; архитектура рассчитана на 10 000 (серверная
  пагинация, bbox-фильтр, кластеризация маркеров при zoom < 12).
- Graceful degradation: при недоступности 2ГИС/карты данные показываются списком/таблицей.
- Ленивая загрузка тяжёлых маршрутов (аналитика, паспорт, доступность), code-splitting
  вендоров, скелетоны; `AccessibilityPage` — отдельный чанк (~22 КБ).
- Ретраи с экспоненциальной задержкой (макс. 3) в клиентах 2ГИС.

## Безопасность (§9)

- Валидация входа (`class-validator`, whitelist), CORS-whitelist, helmet, rate limiting.
- pino-http с `redact` секретов и ПДн; логи без содержимого жалоб.
- Медиа — вне webroot (`/var/data/media`), раздаются отдельным префиксом `/media`.
- RBAC (public/editor/moderator/admin) и JWT+ЕСИА — итерация 6 / этап 2.
- 152-ФЗ: согласие на обработку ПДн в форме жалобы, минимизация состава данных.

## Импортозамещение (§3)

Все компоненты — открытое ПО для контура заказчика: PostgreSQL заменяем на Postgres Pro
без переделки SQL (стандартный SQL + PostGIS), Node/React/NestJS/MUI — Open Source.
Единственная внешняя зависимость — сервисы 2ГИС (риск описан в README); смена
картографического провайдера допускается через слой абстракции `MapProvider` (этап 4).
Развёртывание полностью on-premise — `docker compose` в закрытом контуре.
