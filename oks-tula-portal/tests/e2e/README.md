# E2E-тесты (Playwright)

Сценарии сквозного тестирования портала (§13 ТЗ). Запускаются против **поднятого стека**
(в песочнице CI-разработки Docker/PostgreSQL могут отсутствовать — тогда e2e выполняются
на машине заказчика).

## Запуск

```bash
# 1. поднять стек
docker compose up --build -d

# 2. установить браузеры (один раз)
npm --prefix tests/e2e install
npm --prefix tests/e2e run install:browsers

# 3. прогнать сценарии
npm --prefix tests/e2e run test
# или с UI-режимом
npm --prefix tests/e2e run test:ui
```

`baseURL` задаётся переменной `E2E_BASE_URL` (по умолчанию `http://localhost:8080`).

## Покрытие

- **Дымовой (итерации 0–1):** главная загружается и показывает цифры реестра; страница
  карты показывает список и счётчик «Показано N из M»; `/api/health` отвечает.
- **Полные 5 ключевых сценариев §13** подключаются по мере готовности функциональности —
  см. `docs/ROADMAP.md` (итерации 2–6):
  1. фильтр → карточка объекта → скачать PDF-паспорт;
  2. сравнение «До/В процессе/После» + таймлапс;
  3. изохрона 10/15 мин, повторный клик не вызывает API (кэш);
  4. «светофор» по сфере + drill-down МО;
  5. подача жалобы → номер обращения → отслеживание → модерация в админке.
