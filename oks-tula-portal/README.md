# Интерактивный портал объектов капитального строительства Тульской области

Публичный портал Министерства строительства Тульской области о строящихся и введённых
объектах капитального строительства (ОКС): карта на 2ГИС, карточки объектов, аналитика,
зоны пешей доступности, «светофор» социальной нагрузки муниципалитетов и форма сообщения
о проблемах на стройплощадке.

Монорепозиторий: **React 18 + TypeScript + Vite** (SPA), **NestJS + Prisma** (REST API),
**PostgreSQL 16 + PostGIS 3.4** (БД), **2ГИС MapGL** (карта). Поднимается одной командой.

---

## Быстрый старт (Docker)

```bash
cp .env.example .env
# задайте в .env как минимум POSTGRES_PASSWORD и (для живой карты) VITE_MAPGL_KEY
docker compose up --build
```

Готово:

- **Портал (web):** http://localhost:8080 (карта — `/map`, зоны доступности и «белые пятна» — `/accessibility`, аналитика — `/analytics`)
- **API + Swagger:** http://localhost:8080/api/docs (проксируется nginx) или http://localhost:3001/api/docs
- **Healthcheck:** http://localhost:8080/api/health
- **PostgreSQL:** localhost:5433 (только локальный интерфейс; для psql/DBeaver)

При первом старте контейнер `api` автоматически: ждёт БД → применяет миграции
(`prisma migrate deploy`) → прогоняет ETL (отчёт о качестве) → сидирует реестр
(95 объектов), границы МО, справочники и демонстрационные данные.

> Требуется только Docker с Compose v2. Внешние ключи не обязательны — портал
> полностью функционален в демо-режиме, кроме отрисовки карты (нужен публичный ключ MapGL).

### Получение демо-ключа 2ГИС MapGL

1. Зарегистрируйтесь на <https://platform.2gis.ru>.
2. Создайте ключ для **MapGL JS API** (публичный, для отрисовки карты в браузере).
3. В кабинете ограничьте ключ списком доменов (например, `localhost`, ваш домен).
4. Запишите ключ в `.env` → `VITE_MAPGL_KEY=...` и пересоберите web
   (`docker compose up --build web` или `npm run dev:web` для разработки).

Без ключа вместо карты показывается понятная заглушка с этой инструкцией; список и
карточки объектов работают (graceful degradation, §9 ТЗ).

Для изохрон и геокодинга (боевой режим) дополнительно нужны **секретные** ключи
`ROUTING_API_KEY` (Isochrone API) и `CATALOG_API_KEY` (Catalog/Search API) — они
используются **только на бэкенде** и никогда не попадают в клиентский бандл или логи.

## Разработка без Docker

```bash
npm install
npm run build            # shared → etl → api → web (проверяет типы и собирает всё)
npm run test             # vitest: ETL, нормализация, качество данных, формулы, изохроны/доступность (223 теста)
npm run lint             # ESLint (TS strict, без any)
npm run etl:dry          # ETL без БД → reports/data_quality.md + data/processed/*.json
```

Для локального запуска API/DB нужен PostgreSQL+PostGIS (например, `docker compose up db`),
затем:

```bash
export DATABASE_URL="postgresql://oks:...@localhost:5433/oks_portal"
npm run db:migrate       # prisma migrate deploy
npm run db:seed          # ETL + справочники + мок-данные в БД
npm run dev:api          # NestJS на :3000
npm run dev:web          # Vite на :5173 (прокси /api → :3000)
```

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example). Ключевые:

| Переменная | Назначение |
|---|---|
| `POSTGRES_PASSWORD`, `DATABASE_URL` | доступ к БД (секрет) |
| `VITE_MAPGL_KEY` | **публичный** ключ 2ГИС MapGL (попадает в бандл web) |
| `ROUTING_API_KEY`, `CATALOG_API_KEY` | **секретные** ключи 2ГИС (только бэкенд) |
| `REGION_ID` | регион 2ГИС «Тульская область» = `36` (проверено фактически) |
| `GEOCODER_PROVIDER`, `ISOCHRONE_PROVIDER`, … | `mock` \| `live` — режимы интеграций (§10) |
| `ISOCHRONE_MOCK_GEOMETRY` | в демо-режиме: `true` — зоны строятся геометрической моделью с бейджем «ДЕМО-ДАННЫЕ», `false` — честное «Нет данных» (Ф4) |
| `CACHE_TTL_ISOCHRONE_DAYS`, `CACHE_TTL_POI_DAYS` | срок жизни кэша зон и POI-снимка в PostGIS (по умолчанию 30 суток) |
| `ISOCHRONE_BATCH_MAX_OBJECTS`, `POI_MAX_PAGES` | лимиты пакетного режима и расхода квоты 2ГИС |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | первичный администратор (создаётся при сиде) |
| `WEB_PORT`, `API_PORT` | порты (8080 / 3000) |

Секреты — только в `.env` / `.env.local` (исключены из git). В репозитории `.env.example`
с пустыми значениями (§1, §15.11).

## Ограничения демо-режима (честно)

Портал работает без внешних ключей (кроме MapGL). В демо-режиме:

- **Геокодинг не выполняется** — координаты **не выдумываются**. Из 37 объектов без
  координат 21 вообще не имеет адреса; они показываются в центре муниципального
  образования с пометкой **«местоположение уточняется»** и не участвуют в расчёте изохрон.
  Счётчик таких объектов виден на карте и в отчёте качества (§6.3 п.7).
- **Зоны пешей доступности (Ф4)** работают и без ключей, но честно: без `ROUTING_API_KEY`
  пешеходную сеть 2ГИС получить неоткуда, поэтому зона строится **явной геометрической
  моделью** (радиус = время × скорость пешехода с детерминированным «рельефом»), помечается
  `isMock`/«ДЕМО-ДАННЫЕ» и сопровождается дисклеймером «не является расчётом по пешеходной
  сети». Отключить модель: `ISOCHRONE_MOCK_GEOMETRY=false` — тогда вкладка «Доступность»
  показывает «Нет данных» с причиной. Боевой расчёт: `ROUTING_API_KEY=...` +
  `ISOCHRONE_PROVIDER=live`; кэш в PostGIS исключает повторные обращения к API (§4.2).
- **POI внутри зоны (детсады, школы, поликлиники, жилые дома)** без `CATALOG_API_KEY`
  не запрашиваются и **не выдумываются** — в отчёте доступности «Нет данных» с причиной.
  Соседние объекты той же сферы берутся из реального реестра ОКС (расстояние — по прямой:
  Routing API 2ГИС на текущей подписке недоступен, §4.6). Население в зоне — оценка
  «плотность МО × площадь зоны» на демо-населении (помечено).
- **Закупки (ЕИС), обращения (ПОС), камеры, снимки «до/после»** — адаптеры с
  мок-реализациями; данные помечены `isMock` и бейджем «ДЕМО-ДАННЫЕ» (§10, Приложение C).
- **Границы МО** — OpenStreetMap (упрощение ~85 м), подлежат замене официальными (§6.3).
- **Население** — демо-значения с указанием источника и года; заменить выгрузкой Росстата.

### Организационный вывод (зафиксирован по результатам прогона, §6.3)

Геометрию **42 активных объектов** (в первую очередь **21 объекта без адреса**) нельзя
получить автоматически — требуется официальный запрос координат у заказчика. Наивный
геокодинг «адрес → первый результат» непригоден: 2ГИС подменяет одноимённые улицы
(измерено в ТЗ). Автоматический контроль качества уже ловит расхождения «точка vs адрес»:
например, объект №7 «Крытый тренировочный манеж … (Косая гора)» имеет координату в
Ясногорском районе при заявленном «АМО г. Тула» (~43 км расхождения) — случай отправлен
на модерацию, координата из реестра **не перезаписана**.

### Известные проблемы данных (см. `reports/data_quality.md`)

- Колонка «Фото» в 2 записях содержит **даты**, а не ссылки — ошибка источника; сохранено
  в `photo_date` и `raw`, в UI как фото не показывается.
- 2 пары объектов с идентичными координатами — разводятся на карте (кластеризация/«разноска»).
- Ячейка «Подрядчик» иногда содержит контрактные реквизиты («№ … от …») — извлекаются
  отдельно, организация нормализуется.
- «Пакетное» заполнение дат (передача ЗУ = РНС = контракт = ЗОС = акт у многих строк) —
  не ошибка, но фиксируется в отчёте.

## Данные и атрибуция

- **Реестр ОКС** — ведомственная выгрузка Министерства строительства Тульской области.
  Хранится как есть в `data/raw/objects.csv`; каждая производная цифра трассируется к строке.
- **Границы МО** — © участники [OpenStreetMap](https://www.openstreetmap.org/copyright),
  лицензия ODbL, получено через Overpass API 13.09.2026.
- **Карта** — [2ГИС](https://2gis.ru). При разработке геоданные удобно проверять через
  **MCP-сервер 2ГИС для AI-агентов**: <https://docs.2gis.com/api/ai/mcp-server/overview>.
